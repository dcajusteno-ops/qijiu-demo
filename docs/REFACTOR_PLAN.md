# Comfy Manager 重构收敛计划

当前基线版本：`v3.0.0`  
整理日期：`2026-04-21`

## 1. 这份计划的目的

这份计划不再以“加功能”为主，而是记录当前项目如何在不破坏主流程的前提下持续收敛复杂度。

当前目标是：

- 降低单文件复杂度
- 降低前后端耦合
- 稳定发布链
- 让后续继续开发时更容易定位问题

## 2. 当前已经完成的收敛

### 2.1 后端目录整理完成

原先大量 Go 逻辑堆在根目录，当前已经完成这一步：

- 后端主体迁移至 `desktop-source/backend/`
- 根目录只保留 Wails 入口层
- 按职责归类成：
  - `app_core_*`
  - `app_feature_*`
  - `app_support_*`
  - `app_types_*`

### 2.2 前端已完成的拆分

原来过重的前端逻辑已开始收敛：

- `useGalleryHelpers.js`
- `useWorkbenchFilters.js`
- `useGalleryData.js`
- `useLibraryMeta.js`
- `Lightbox` 相关组件拆分

### 2.3 发布链收敛完成

当前发布链已经恢复稳定：

- `wails build -clean` 可生成桌面 exe
- `wails build --nsis -clean` 可生成 Windows 安装包
- 根目录产物可同步覆盖

## 3. 当前阶段明确不做的事

为了避免继续把工程拆得过散，当前阶段明确不做：

- 不继续深拆 Go package
- 不大规模更换技术栈
- 不引入新的状态管理框架
- 不为了“更优雅”重写稳定逻辑

## 4. 当前推荐原则

### 4.1 后端原则

- 新增功能优先归入现有 `backend/` 分组
- 不再把大量业务逻辑写回根目录
- 如果一个 helper 只服务单个功能，优先就近放置

### 4.2 前端原则

- 页面负责视图组织，不承担过多数据细节
- composable 负责状态和数据流，减少组件内堆逻辑
- 先做职责边界调整，再考虑体验微优化

### 4.3 文档原则

- 版本升级时优先同步软件内文档和外部 README
- 先保证文档可读、可发布，再追求文风统一
- 发布版本必须同步产物、版本号和文档索引

## 5. 后续可继续推进的方向

### 5.1 优先级高

1. 统一修正剩余编码历史文案
2. 继续减轻 `App.vue` 和个别大组件的入口复杂度
3. 把设置中心中的配置项再分层整理

### 5.2 优先级中

1. 继续评估图库筛选链的可测试性
2. 为自动规则与提示词助手补更多边界说明
3. 评估是否补一份架构图或数据流图

### 5.3 优先级低

1. 进一步拆更细颗粒度模块
2. 对现有稳定功能做风格性重写

## 6. 当前风险点

- 历史编码问题仍可能残留在零散中文文案里
- 生成产物与源码目录重构后，前端绑定兼容要继续留意
- 发布时如果忘了同步根目录 exe / installer，用户拿到的可能不是最新版本

## 7. 当前建议

如果继续推进项目，建议用下面的顺序：

1. 稳定 `v3.x` 发布流程
2. 继续做文案与编码清理
3. 再做局部组件和 composable 收敛
